Privacy and data handling

Privacy policy

AIM VPS Backup is a personal, self-hosted integration used by its operator to store encrypted recovery archives in the operator's Google Drive account.

Effective date: October 9, 2026

1. Who operates this integration

This is a private-use application operated through the GitHub account pbcristi. It is not a public backup service and does not solicit third-party customer accounts. General questions can be submitted through the public repository issue tracker; never include secrets or private financial information in an issue.

2. Google data accessed

The application uses Google OAuth 2.0 and requests only the Google Drive API permission https://www.googleapis.com/auth/drive.file. This permits it to create, view, list, download, update and delete files or folders created by the application as needed for backup delivery, verification, retrieval and operator-authorized retention. It does not request full access to unrelated files in the account.

Google provides the authorization required to access the operator's selected Drive account. OAuth access and refresh tokens are handled by the private, self-hosted backup client, not by this public website.

3. What is transferred and why

The integration is intended to transfer encrypted backup archives from the operator's server to Google Drive for disaster recovery. Backup data is encrypted before transmission to Drive; plaintext database records, portfolio information and cryptographic recovery keys are not intentionally uploaded through this workflow. Google Drive may process file metadata such as filenames, sizes, timestamps and API activity as part of its storage service.

The integration may read back an encrypted archive to check transfer integrity or assist recovery. It does not use Google Drive data for trading, profiling, advertising, AI training or selling information.

4. Storage and security

Encrypted archives reside in the operator's Google Drive account. Backup encryption and key recovery are managed separately from Google Drive. The self-hosted client stores its OAuth configuration on the operator-controlled system, rather than in this GitHub Pages website. As with any cloud account, access also depends on the security of the operator's Google account and connected devices.

This website has no sign-in form, does not ask for OAuth tokens or passwords, and does not embed third-party analytics scripts. GitHub Pages, as the website host, and Google, as the API and storage provider, may process ordinary technical logs under their respective policies.

5. Sharing and limited use

Google user data is used only to perform the requested backup, verification, recovery and retention operations. The operator does not sell Google user data or disclose it to advertising platforms or unrelated third parties. Access tokens and the contents of the operator's Drive are not displayed on the public website or published in this repository.

6. Retention and deletion

Backup archives remain in the operator's Google Drive until they are manually deleted or a retention policy is subsequently configured and enabled. Automated retention is not implied merely by granting OAuth access. The operator can delete uploaded files in Google Drive and can remove local OAuth authorization from the backup client. Deleting a cloud archive does not necessarily remove other independently held recovery copies.

7. Revoking Google access

  1. Visit Google Account connections and find the AIM VPS Backup connection.
  2. Remove the application's access to Google Drive.
  3. If desired, also delete the encrypted backup files from Google Drive and remove the locally stored rclone authorization.

Revoking authorization stops future access through that authorization; it does not automatically delete archives already saved to Drive.

8. Changes

This policy will be updated if the application starts using additional Google permissions or materially changes how backups are handled. The current policy is published at this URL and is linked from the application homepage.

9. Contact

For questions about the application's privacy practices, use the public GitHub issue tracker without providing sensitive account information.
